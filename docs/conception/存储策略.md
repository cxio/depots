# 存储策略

本文讨论公益节点在收到探测包后，如何判断一个数据对象是否值得补存，以及已持有副本时是否可以保守淘汰。目标是在没有中心协调、没有显式回复的前提下，让网络副本数量围绕合理密度自组织稳定。

核心原则：

- 不能只凭一次“大跳数”就补存，应综合空间、时间和本地资源信号。
- 补存是概率行为，越靠近空白区中心，概率越高；外围节点按衰减概率响应，避免羊群效应。
- 淘汰必须比补存更保守，避免副本在补存与删除之间振荡。


## 探测信号

### 包级信号

探测包的 `Hops` 表示从发起方到当前节点之间连续经过了多少个“未持有该数据”的节点。跳数越大，说明该方向上的副本空白区越大，补存基准概率越高。

剩余 `TTL` 用来判断风险程度。如果跳数接近上限仍未被持有者截停，说明该数据可能已经极度稀缺；此时应提高优先级，但仍需先做可获取性检查，避免追逐已经彻底丢失的数据。

若探测包带签名或工作量证明，节点只统计合规包。例如要求发起方完成约单核 500ms 的 PoW，用来过滤低成本伪造和骚扰。

### 拓扑信号

同一探测 ID 从多少个邻居到达，是判断自身位置的重要依据。持有者不会继续转播探测包，因此：

- 若多个邻居都送来同一探测，且跳数普遍偏大，说明本节点可能位于数据空白区内部，补存价值较高。
- 若只有少数邻居送来，其他方向没有动静，说明周围可能已有持有者截停，或本节点只在空白区边缘，补存价值较低。

还应比较多条路径上的跳数分布。如果不同邻居送来的跳数都偏大，可信度较高；如果差异悬殊，可能是局部绕路、拓扑噪声，或中继行为异常。

### 历史信号

单次探测噪声很大，节点应记录同一 ID 的近期观测结果，包括来源邻居、跳数、到达次数和时间。

更可靠的补存信号来自历史累积：同一 ID 在一段时间内被不同公益节点多次探测，并且跳数持续偏大，说明副本确实稀缺。若历史跳数呈上升趋势，也表示副本可能正在减少，应提高补存优先级。


## 补存决策

补存决策可以视为一个加权评分，也可以实现为本地策略函数。建议至少包含以下因素：

- `Hops`：跳数越大，基础分越高。
- 多路径到达率：到达邻居越多，且跳数越一致，置信度越高。
- 探测频率：短期内多次、来自不同发起方的探测更可信。
- 数据大小：小对象可以更积极补存，大对象需考虑带宽和磁盘成本。
- 本地预算：公益存储空间充足时放宽门槛，空间紧张时只响应高风险对象。
- 当前负载：已有下载任务较多时，应延后或放弃新的补存。

为了避免同一层大量节点同时补存，应按概率响应。概率可随跳数增长而升高，但同一跳数层的期望补存数应保持在小常数附近。换言之，节点越确定自己处在空白区，越可能补存；但不能让整片外围节点一起行动。


## 退避与去重

节点决定补存后，不应立刻下载，而是先随机退避一段时间。退避期间如果再次收到同一 ID 的探测，并且跳数明显变小，说明附近可能已经有人补上了副本，此时可以取消补存。

短时间内收到的同一探测 ID 应直接去重，不重复转播，也不重复触发补存判定。这可以降低多个公益节点同时探测冷门数据时造成的网络放大。

真正下载前，还应先做轻量可获取性预检，例如查询 DHT 或链上元数据。如果元数据、种子或可取回路径都不可见，应放弃本次补存。


## 副本淘汰

如果系统只有补存没有淘汰，长期副本数只会增长。持有者虽然不会继续转播探测包，但仍可以从探测到达情况里获得信号。

持有者若经常收到 `Hops` 很小的探测，说明发起方就在附近，且该区域已经被自己或邻近副本覆盖。若还观察到某个 ID 的探测总是在附近停止，或邻居长期不再转发该 ID 的探测，也可推测局部副本密度偏高。

此时节点可以按较低概率淘汰副本。淘汰策略应满足：

- 只在本地空间紧张或副本明显过密时触发。
- 需要多次、跨时间窗口的信号确认。
- 淘汰概率低于补存概率，且最好带冷却期。
- 白名单、付费委托或本地用户明确保留的数据永不自动淘汰。

这样可形成闭环：空白区通过概率补存修复，密集区通过保守淘汰降密，副本数在目标密度附近波动。


## 抗滥用与容错

探测信息来自泛洪传播，天然具有多路径冗余。节点不必完全相信单个邻居，而应对同一 ID 的多个观测做合并或投票。

对于本地位图或类似的持有状态摘要，可以采用并集、投票或更保守的确认策略。例如某个邻居声称某 ID 已被清零，但多个独立邻居仍显示未被覆盖，则节点不应立即相信单一路径。反过来，如果存在有效持有证明，也可以优先采信，以减少无意义补存。

总体上，策略应把少数恶意中继、局部绕路和偶发噪声视为常态，通过多路径、多次观测和本地资源约束来抹平误差。


## 小结

这是一种去中心化、自组织的副本修复机制。探测包在副本空白区继续传播，各节点根据自己看到的跳数分布、到达次数、历史趋势和资源状态独立决策，不需要全网统计，也不需要中心协调。
