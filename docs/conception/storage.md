# 存储设计参考

本存储方案采用本地文件系统，主要适配个人PC。原则上，存档文件的大小没有限制，但通常不支持大于**64GB**的文件。


## 存储策略

三项措施：**策略函数**、**白名单**、**黑名单**。

> **说明：**
> 仅用于探测包评估，数据发布包的评估由应用自行设计&实现，不在此列。


### 策略函数

由存储节点自己编写（Lua 或 Go），在数据查询无果时触发（在黑白名单之后）。

函数声明：`func(id []byte, info *MetaInfo, hops int) bool`，其中：

- `id` 为数据索引，最长32字节。
- `info` 数据元信息，含 Kind, Title, Size, License 等基本信息。
- `hops` 为转播跳数，≤15。

如果函数返回 true，则表示需要补充存储。


### 优先级

检查优先级： *白名单 > 黑名单 > 策略函数*

如果某一目标同时存在于黑名单和白名单中，则白名单有效。如果黑名单中存在，则不会再调用策略函数。


## 本地存储

前置存在性判断可能采用数据ID的如布隆过滤器。


### 文档元信息

存档的数据除了文档本身外，还会有一个元信息文件，包含了对文档基本信息的记录。

通常有如下条目：

- 文件：文档文件名，含扩展名（如 .tar, .zip）
- 类型：实际内容的 MIME 类型
- 标题：文档的名称（主标题）
- 概要：文档的内容摘要、大纲
- 大小：打包文档的大小（bytes），通常自动检查而来
- 语言：内容所属语种，可多语种并列（首项为主）
- 作者：文档的原始作者，多位并列
- 创建时间：文档原始创建时的时间，可选
- 许可证：文档的原版许可声明，可选。公共域内容可能无明确版权
- 指纹：文档本身的哈希（`SHA3-512`）摘要，非分片树根
- 清单：如果是打包文档，包内文件名列表，可选
- 备注：特定档案可能有的额外说明，可选


### 存档路径

文档的分片哈希树根称为 `TID`。

存档按「年度/TID 两字节分组/TID片段」，分4层目录结构存储。顶层年度便于管理，末端为 TID 的 16 字节片段。

```go
2026/                           // 年度（存档时间），友好
    A_0fff/                     // 一级：TID[0:2] % 0x1000，16进制表达，前置 A_
        B_0fff/                 // 二级：TID[2:4] % 0x1000，16进制表达，前置 B_
            TID[:16]/           // 存档目录，TID 序列前段
                [file].xxx      // 存档文件，名称与.meta内「文件」字段相同
                meta.json       // 文档元信息配置
            files.list          // 各存档 "ID[:4] => Title | File" 对应清单（人工友好）
                                // ID[0:4]为默认长度，如果重名冲突则逐字节延长
```

单年度两层 4096 分组最多可以离散**16M**区隔，对于普通的家用个人PC应当已足够。



## 存储激励

数据驿站节点的存储通常是自由和自愿的，这是一种分享的精神。

当然，有的用户需要长期的可靠存储，此时用户可能需要支付必要的佣金，这通过双方协商完成，佣金通常是区块链代币形式。

P2P文件分享式存储近似于公共域逻辑，如果文档为开放许可证，允许存储节点挖掘数据价值，则额外的代币激励就无关紧要了。在以数据为基础资源的 AI 时代，如此开放式的存储方式可能也有它的价值。
