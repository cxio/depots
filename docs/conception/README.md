# 数据驿站（Depots）

在传统的数据分享应用里，针对想要的数据，用户可以根据数据的索引ID，从拥有数据的多个节点那里获取。

拥有数据的用户是零散的，有的用户即便拥有数据，也不一定在线或开启数据分享。用户与用户之间没有关联，分享是一种极其松散的逻辑。对于很多古老的数据，由于缺乏经济驱动力，很难找到相应的数据节点。

总结原因大概有如下两点：

1. 缺乏利益驱动。久远数据会随着热度的下降，用户不再保存，逐渐淡出分享网络。
2. 缺乏感知机制。没有一种机制可以让用户知道哪些数据稀缺，需要存储。

数据驿站就是为解决这一问题而设计的。数据驿站网络，是一个开放的通用的数据存储&服务网络。


## 开放式存储

### 紧缺性感知

网络节点对数据的请求通过广播查询，没有目标数据的节点会转播请求，拥有数据的节点则回应并不再转播。

如果请求每转播一次就跳数加一，则通过跳数的大小，节点可以感知请求广播的距离。总体上来说，广播的距离越远，说明数据越紧缺。这可以促使部分节点补充存储（取决于节点的存储策略）。

这种协作存储可能会有较大的冗余度，但同时也可能无法100％保证数据的完备性。如果某些数据请求很少，在长时间的*淡忘*下，它们很可能就会慢慢消失。

因此，这需要一种措施，来保证数据请求的广泛性。


### 数据心跳

如果有一些节点，可以对广泛的数据索引执行间歇性的请求（实为一种探测），就可以持续让网络上的节点知道那些数据的存储丰度。这种探测，可以称之为心跳。

数据心跳是由一些公益节点发出的，数据的广度由这些节点来保证。通常来说，它们主要关注那些创建时间较久的数据。对于区块链数据来说，因为有确定性的索引，所以完备的探测就不再是个问题了。

理论上，这些公益节点在地理位置上均衡分布会更好。因为只是简单的探查消息，应该不需要太多。


### 标识寻址

在数据请求里会有一个数据索引，它通常是数据的ID（如数据内容的哈希），但事实上，数据索引也可以不是数据ID……这只是一个标识：它既能标识数据，也可以标识一种服务。

传统的网络通过域名寻址查找服务器，而这里的ID是自定义的，明显更灵活一些。


## 数据站群

对数据服务节点的奖励，可通过数据源节点向用户提供自己的区块链代币地址来实现。

奖励并不必然，但这是一条途径。某些区块链的实现会关注这一点：它们委托驿站&数据网络存储自己的历史区块和相关数据。

驿站不必是单个实体，如果多个服务节点声明同一个代币收益地址，实际上就创建了一个虚拟的数据站群（看起来属于某一实体）。

声明共同的收益地址可以使该地址在更广的范围内可见，因此也更容易被认可。


### 开放评估

如果创建了数据站群，其管理者需要评估成员节点的服务效率，为分发奖励提供依据。

但P2P的自由模式让嵌入第三方管理成为一个复杂问题，并且可能破坏P2P的简单性和灵活性。因此这里提供一个思路：**开放式评估**。


#### 协议补充

数据服务节点在向应用提供数据服务前，会向对方传递一个收益地址以接收可能的奖励。这里，我们可以增加一个可选的字段：**身份ID**，用于标注自己。这通常就是一个相同链的账户地址，站群管理者可以据此发放收益。

身份ID可能由管理者发放，进行中心化管理。也可能是开放的自由加入模式（去中心化），由用户自己提供。

身份ID只对数据站群的管理者有用，其它第三方应用节点只会简单忽略。这种提供是必须的，它用于下面「匿名探测」机制的实现。


#### 匿名探测

如果采用非中心化的开放式合作，管理者需要一种评估成员节点服务质量的方式。

**匿名探测**：管理者像普通客户一样向对方请求服务，如果对方发布的收益地址与本群相同，即为站群成员。然后记录其身份ID，对其服务质量进行评估。

因为普通节点也会要求提供身份ID，所以服务节点并不清楚对方是否为管理者。匿名的请求使得服务节点很难做讨好型作弊。


#### 开放性

数据站群的收益地址通常是公开的，这很方便吸引离散的自由节点的加入。

如果收益地址公开，只要你愿意，通过匿名探测的方式，实际上任何人都可以评估一个站群，甚至了解这个站群的奖励分配公允性如何。


## 其它数据

数据驿站网络主要用于区块链的公共存储，数据索引可能是确定性的区块ID或交易中的附件ID。

但如果有市场需求，本数据存储网络也是通用的——只要有服务节点愿意存储，有应用需要服务并提供激励即可。
