# 本地存储设计

本存储方案采用本地文件系统，主要适配个人PC。原则上，存档文件的大小没有限制，但通常不支持大于**64GB**的文件。

网络检索键采用文档的分片哈希树根 `TID`，固定 32 字节。文档数据本身的 `SHA3-512` 指纹只存在于元信息里。


## 存储策略

三项措施：**策略函数**、**白名单**、**黑名单**。


### 策略函数

这是一个复杂的综合评估，详见 [存储策略](存储策略.md) 设计。

若评估函数返回 true，表示数据「值得去要」。无论白名单还是策略函数要求补存，写入前都应先考虑取少量分片验证（默克尔树证明，适用有分片逻辑的较大文件）。


### 优先级

检查优先级： *白名单 > 黑名单 > 策略函数*

如果某一目标同时存在于黑名单和白名单中，则白名单有效。如果黑名单中存在，则不会再调用策略函数。


## 本地存储

本地是否已经持有某个 TID，可以用布隆过滤器做前置判断。过滤器只是加速，命中与否最终以磁盘上的 TID 为准。

删除存档时，应把其 TID 记入删除集，或重建过滤器。**注**：只删文件会让过滤器的判断无效。


### 文档元信息

存档的数据除了文档本身外，还会有一个元信息文件，包含了对文档基本信息的记录。

通常有如下条目：

- 文件：文档文件名，含扩展名（如 .tar, .zip）
- 类型：实际内容的 MIME 类型
- 标题：文档的名称（主标题）
- 概要：文档的内容摘要、大纲。发布包的 Summary 可以写到这里
- 大小：打包文档的大小（bytes），通常自动检查而来
- 语言：内容所属语种，可多语种并列（首项为主）
- 作者：文档的原始作者，多位并列
- 创建时间：文档原始创建时的时间，可选
- 许可证：文档的原版许可声明，可选。公共域内容可能无明确版权
- 指纹：文档本身的哈希（`SHA3-512`）摘要，非分片树根，不参与网络检索
- 清单：如果是打包文档，包内文件名列表，可选
- 备注：特定档案可能有的额外说明，可选

网络上的 MetaInfo 只有种类、标题、大小、许可证。探测包没有概要。语言、作者、指纹和清单只留在本地。


### 存档路径

存档按「年度 / TID 两字节分组 / 完整 TID」放。顶层年度方便人查看。查找以完整 TID 为准，靠 TID 索引定位，不靠扫描年份。

```go
2026/                           // 存入年度，只是位置，不参与身份
    A_0fff/                     // 一级：TID[0:2] % 0x1000，16进制表达，前置 A_
        B_0fff/                 // 二级：TID[2:4] % 0x1000，16进制表达，前置 B_
            TID/                // 完整 32 字节，目录名即键
                [file].xxx      // 存档文件，名称与 meta 内「文件」字段相同
                meta.json       // 文档元信息配置
            files.list          // 离线生成的 "TID前缀 => Title | File" 清单
                                // 前缀默认 4 字节，冲突再逐字节延长
                                // 收发和补存不读它
```

同一 TID 全盘只留一份。已经存在就不再按新的年度复制一份。

单年度两层 4096 分组最多可以离散**16M**区隔，对于普通的家用个人PC应当已足够。



## 存储激励

数据驿站节点的存储通常是自由和自愿的，这是一种分享的精神。

当然，有的用户需要长期的可靠存储，此时用户可能需要支付必要的佣金，这通过双方协商完成，佣金通常是区块链代币形式。报价如何传送见网络设计里的 Deposit，在本实现中，它不影响策略函数的决策。

P2P文件分享式存储近似于公共域逻辑，如果文档为开放许可证，允许存储节点挖掘数据价值，则额外的代币激励就无关紧要了。在以数据为基础资源的 AI 时代，如此开放式的存储方式可能也有它的价值。

> **说明：**
> 通常是开放许可证的内容才会进入探测和补存，协商佣金的委托存储由双方自行完成。
