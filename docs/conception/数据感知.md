# 数据感知

网络节点对目标数据发送探测包，通过广播扩散，沿途节点检查自身是否为该数据的持有者，然后设置标记或终止转播。通过这一机制，其它节点获得某种信号，然后即可进行综合评估。

与数据的询问和发布不同，探测包是一个特殊的请求，不需要数据持有者节点的回复。

为了更好的可靠性，这里采用两种模式：「*简单终止*」和「*信息传递*」。

两种模式同时运行，但以「简单终止」为主，仅在初步判断数据较稀有或不确定时，启动「信息传递」模式补充探测，获取更多信息。


## 共性设计

精简数据结构，极致轻量运行。探测包数据量不超过 130 bytes。

探测包起始跳数为零，遵循跳数**递增**逻辑，最大跳数 `12`，分两段式扩散：**7**跳之前扩散率 `3`，之后为 `2`。这可以严格约束洪泛规模，也因此，探测本身的容量可随网络后期扩张而增长。

另外也有频率限制：节点接受一个对端的探测包为 **10次/秒**（非重复）。这是一个综合平均值，实现可采用令牌桶形式，以容忍高频发布时的峰值流量，桶深为 *50*。


## 模式A：简单终止

当探测包抵达数据持有者时，节点只是简单终止转播，没有任何其它行为。没有数据的节点正常转播……直到抵达跳数上限。


### 机制设计

简单终止基于如下理由：

- 终止截断了信息向后表达，但提供了「空无」信号——没有激活 => 变冷。其**合理性：**
    - 其它地方已经有存储了，自己无需补存，因此也无需任何信号。
    - 若自己是持有者，则根据自身的淘汰策略行事（惰性淘汰），也无需其它考虑。
    - 攻击者没有更多的手段可以制造向后影响。停止转播与自身不存在同义（仅占位路径节点）。

- 无数据持有者的路径上，探测包长路径抵达，成为激活信号 => 变热。
    - 节点的存储策略评估可获得路径位置（跳数）参考。
    - 攻击者在此与普通节点没啥区别，只能升高跳数，但后果只是缩减下游扩散，让下游跳数读数偏高。

探测包中的数据为明文，在没有全局协商/签名认证的情况下，攻击者能自由修改路径上其它节点设置的任意状态值，实现向后破坏。因此「简单终止」模式通常应当作为主模式使用。


### 探测包

任意节点都可以发出探测包，但需支付工作量。合计字节数 124 bytes。

```go
(2)     Ver:        版本号。
(1)     Mode:       当前模式：A
(8)     ID:         标识此探测包。
(8)     Timestamp:  起始时间戳（Unix，毫秒）。
                    与 ID 字段一起，足够唯一标识本探测包
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
(32)    DataKey:    数据完整键，32 字节。
(1)     Hops:       跳数累计：
                    首跳值 0，末端最高 12。
                    [1-7]   => 扩散率 3; 3^7 = 2187
                    [8-12]  => 扩散率 2; 2187 * 2^5 = 69_984
                    合计触达节点：138_874
(32)    Proof:      探测工作量证明，详见下文。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
以下单向哈希链防止 Hops 被改小：
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
(20)    WayOn:      路途哈希。沿途变化。
(20)    WayEnd:     跳数终点。固定，会绑定到 Proof。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
```


### 单向哈希链

单向哈希链是维护跳数单向递增的机制。

```go
// 源站。Seed 同样每次重新抽取，不外传。
WayOn = Hash(Seed)
WayEnd = WayOn
for i range 12 {
    WayEnd = Hash(WayEnd)
}
Hops = 0

// 接收：
if Hops > 12 {
    return false
}
tmp = WayOn
for i range 12-Hops {
    tmp = Hash(tmp)
}
if tmp != WayEnd {
    return false
}

// 已经走到 12：
// 停止。否则只前进一跳。
if Hops == 12 {
    return
}
Hops = Hops + 1
WayOn = Hash(WayOn)
```

不良中继只能把链多走几步而无法回撤，这会让 `Hops` 变大，剩下的路程变短。这可使得紧缺读数偏高，但影响只限于该单条路径。


### 工作量证明

探测包的工作量设计与询问包类似，只是绑定的字段不同。详见 [Design](Design.md) 相关部分。

```go
// 基础信息：
// 探测包里的不可变字段值。
// domainTag 探测包域标识：depots:Probing@v1
baseInfo := domainTag ||
            Ver ||
            Mode ||
            ID ||
            Timestamp ||
            DataKey ||
            WayEnd
```

其它求解和工作量验证逻辑与「询问包」章节相同。


## 模式B：信息传递

允许数据持有者转播消息，但需设置必要的状态。后续下游节点可获得信息参考。

这些动态设置的状态无法进入初始工作量固化，因此攻击者可以随意修改而无需付出成本。所以与模式A相比，此模式仅为辅助，协助节点完善评估工作。


### 探测包

添加两个 4 Bit 字段，合计字节数 125 bytes。

```go
(2)     Ver:        版本号。
(1)     Mode:       当前模式：B
(8)     ID:         标识此探测包。
(8)     Timestamp:  起始时间戳（Unix，毫秒）。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
(32)    DataKey:    数据完整键，32 字节。
[4]     Holders:    数据持有者计数，4 bits。每过一个持有者加一。
[4]     PinHops:    最后一个持有者跳数，4 bits。
(1)     Hops:       跳数累计。
(32)    Proof:      探测工作量证明。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
以下单向哈希链防止 Hops 被改小：
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
(20)    WayOn:      路途哈希。沿途变化。
(20)    WayEnd:     跳数终点。固定，会绑定到 Proof。
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
```


### 其它事项

新增的两个字段仅与数据持有者有关，持有者修改相应的值，然后转播。

其它如*工作量证明/单向哈希链*等，与「简单终止」模式相同。


## 数据心跳

某些节点通过发布探测包来感知目标数据的存在性，持续运行……通过一定的历史积累，即可评估数据的紧缺性，进而触发补存行为。

执行探测的节点称为心跳节点，心跳探测是一些愿意付出成本的公益节点或利益相关方的事，探测的数据键集通常来源于确定性的清单，如链上索引、节点自己的清单文件、机构组织的档案目录等。

评估是复杂的，详见 [存储策略](存储策略.md)。如果节点最终决定补存，即发送询问请求，查询并拉取数据。

> **实现：**
> 找到数据源后，数据是通过类似 BitTorrent 的文件分享模式获取。
