# 数据驿站（Depots）

在传统的数据分享应用里，针对想要的数据，用户可以根据数据的索引ID，从拥有数据的多个节点那里获取。

拥有数据的用户是零散的，有的用户即便拥有数据，也不一定在线或开启数据分享。用户与用户之间没有关联，分享是一种极其松散的逻辑。

在 AI 驱动的未来，数据的重要性不言而喻。在开放领域，长期的数据保存和分享可能是一个问题。


## 开放式存储

本数据驿站是一个开放的数据存储&分享网络，但与 IPFS/Filecoin 的严肃/严格逻辑不同，这里是松散和自由的。

因为缺乏经济激励，本项目基本上属于一个实验，试图为某些开放的数据存储和检索需求提供服务。


### 紧缺性感知

网络节点对数据的查询请求通过广播扩散，没有目标数据的节点会转播请求，拥有该数据的节点则终止转播。

如果请求每转播一次就跳数加一，则通过跳数的大小，节点就可以感知请求广播的距离。总体上来说，广播的距离越远，说明数据越紧缺，于是有需要的节点就可以启动补充存储。

这种松散的协作方式很难保证数据的完备性，如果某些数据请求很少，在长期*淡忘*之下，它们很可能就会消失。

因此就需要一种措施，来保证数据请求的广泛性。


### 数据心跳

如果有一些节点，可以对广泛的数据索引执行间歇性的请求（探测），就可以持续让网络中的节点了解数据的存储状况。这种探测就称之为心跳。

数据心跳由一些公益节点发出，数据的广度由这些节点来保证。对于区块链来说，因为有确定性的索引，所以完备性不是一个问题。
