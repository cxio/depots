# 数据驿站（Depots）

在传统的数据分享应用里，针对想要的数据，用户可以根据数据的索引ID，从拥有数据的多个节点那里获取。

拥有数据的用户是零散的，有的用户即便拥有数据，也不一定在线或开启数据分享。用户与用户之间没有关联，分享是一种极其松散的逻辑。

数据的重要性不言而喻，但在开放领域，长期的数据保存和分享可能是一个问题。


## 开放式存储

数据驿站是一个开放的数据存储&分享网络，但与 IPFS/Filecoin 的严肃/严格逻辑不同，这里采用松散和自由的模式——任意节点都可以成为存储者和广播探测者。

因为缺乏严谨的经济激励，本项目尚属一个实验：尝试为某些公共开放的数据存储和检索提供服务。


### 紧缺性感知

网络节点对数据的请求通过广播扩散，请求者设定初始的必要参数，在每一跳中：

- 拥有目标数据的节点会创建一个标记（实际为富裕度减额），然后扩散转播。
- 没有目标数据的节点不作任何标记，继续扩散转播。
- 消息广播路径上的节点可通过这些标记（以及跳数），评估目标数据的持有情况。此即为感知。

评估数据在全网的紧缺性是一项复杂的工作，详见 [存储策略](./docs/conception/存储策略.md)。如果节点评估结果是需要补充存储，即启动对该数据的询问和获取。


### 数据心跳

松散的协作方式很难保证数据的完备性，如果某些数据请求很少，在长期的*淡忘*之下，它们很可能就会消失。因此就需要某种措施，来保证数据请求的广泛性，这就是「数据心跳」。

数据心跳是一些公益节点通过某些数据索引/目录，向网络发送间歇性的探测请求，触发局部甚至整个网络对目标数据的紧缺性感知、补充存储，从而维护数据的持久可得性。

区块链附件有确定性的索引，因此完备性不是问题。但本系统是开放性的，探测包可以由任意节点发出，因此任何组织和个人，都可以根据自身需要，用自己的文件清单进行探测，维持心跳。

驿站网络是自由的，因此也是松散的，所以本系统只提供机制，没有其它更多的保证。
